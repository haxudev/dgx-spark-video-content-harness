# 项目报告书（二）· 作品介绍：功能与亮点

> 配套文档：`01-名称-目标-背景.md`、`03-GX10-qwen3.6-使用详情.md`、`04-分镜脚本.md`、`05-开发复盘-团队故事.md`

---

## 一、作品是什么

`podcast-football` 是一条 **agent-first 的足球数据观察短视频自动生产线**。喂进去一份分析数据，吐出来一条可直接发布的竖屏解说视频。同一套引擎支持两种成片形态：

- **双人播客对谈**（`podcast`，v2）：男女双主持「小美 + 小帅」逐场深聊，一问一答，有节奏有观点。
- **单人第一人称解说**（`monologue`）：一位「解局人」用悬念口播讲一场球，与双人版共用同一套四幕画面。

两者共享同一条「解析 → 规划 → 写稿 → 校验 → 配音 → 数字人 → 合成 → 渲染 → 交付」的流水线，只在分镜、口播稿与配音上分叉。

## 二、核心功能总览

### 2.1 输入 → 输出

|              | 双人播客 / 单人解说                                             |
| ------------ | -------------------------------------------------------------- |
| **输入源**   | 任意结构的单场分析 **HTML 报告**，或 `--url` 直接抓网页       |
| **覆盖范围** | 一条视频 = 一场比赛深度解读                                    |
| **主持形态** | 男女双主持 / 单人解局人                                        |
| **输出**     | 1080×1920 竖屏 MP4，H.264+AAC                                 |
| **触发方式** | `harness run <html\|dir\|--url>`                               |

### 2.2 流水线阶段（plan-exec-verify 状态机）

双人 v2 完整 14 阶段：

```
INGEST → PLAN → WRITE → VERIFY_TEXT → AUDIT_TALK → TTS → VERIFY_AUDIO
       → AVATAR → COMPOSE → VERIFY_VISUAL → RENDER → VERIFY_AV → AUDIT_VISUAL → POST
```

每个阶段都由 supervisor 用「计划-执行-校验」封装，自带**重试、回滚、问题路由、升级 escalation**。校验器发现问题时，会把问题类型路由回「能最省事修好它的最早阶段」重跑，而非全量重来。所有中间产物落盘到 `out/<日期>/<match>/`，支持**断点续跑**（`--from TTS --to POST`）。

### 2.3 各阶段职责（精简版）

- **INGEST**：解析 HTML → 通用 `Block[]`，**入口即丢弃所有赔率字段**。
- **PLAN**：生成分镜脚本，v2 是固定四幕。
- **WRITE**：**Agent 现场创作**口播稿（详见亮点）。失败回退确定性模板。
- **VERIFY_TEXT / AUDIT_TALK**：文本合规、术语、句长、双主持节奏、每幕可理解性打分。
- **TTS**：逐句语音合成，**音频即时间基准**，产出精确时间轴。
- **AVATAR**：从版本库**缓存-only**取一段数字人口播片段（绝不联网、绝不触发生成）。
- **COMPOSE**：Handlebars 拼装可渲染网页 + gpt-image-2 封面/背景 + 字幕。
- **RENDER**：hyperframes 无头 Chrome 确定性渲染 → ffmpeg 编码 + 数字人叠加。
- **VERIFY_AV**：ffprobe 校验成片时长与音频时间轴对齐（`|Δ| ≤ 0.5s`）。
- **POST**：SHA-256 指纹、合规审计 `compliance.json`、缩略图、交付清单 `manifest.json`。

## 三、五大亮点

### 亮点 1 · Agent 现场创作，不是套模板

WRITE 阶段是**真正的「一次成稿」LLM 创作**：一整段「结论先行」的 prompt 让 GX10 Qwen3.6 看着「市场派生的简报」现场把整篇稿子写出来，先抛结论、再层层展开。关键防退化设计：

- **`creativeSeed` 随机种子**：让同一场比赛、甚至重复跑同一份数据，也能写出不同措辞的稿子（可用 `HARNESS_WRITE_SEED` 钉死以便复现）。
- **`retries: 2`（共 3 次）**：provider 抖动时坚持重试 agent，绝不悄悄退回「每场雷同」的模板。
- **`authoredBy` 落章**：`dialogue.json` 标记本稿是 `agent` 还是 `deterministic`；一旦在 LLM 可用时回退，抛 `write-agent-fallback` WARN。团队铁律：「如果成片每场听起来都一样，先查 `authoredBy`——那是退回模板了，修好 provider 重跑，不接受模板成片。」
- **确定性模板兜底**：完全离线也能出片，保证 CI 与断网可跑。

### 亮点 2 · 「直白球赛术语」口播规则——反抽象隐喻

为了让「中学文化程度也一听就懂」，系统 prompt 里写死了一条硬规则：

> **比喻只能用足球场上看得见的画面和术语**（控球、反击、压迫、防线、定位球、体能……）；**严禁任何跨领域、文学化、抽象隐喻**——不许出现「门缝 / 裂缝 / 风向 / 暗线 / 窗户纸 / 钥匙开锁 / 一盘棋 / 一部电影 / 资本」这类要观众动脑筋猜的说法。

开场必须**直给**，禁止「这场像两把钥匙开同一把锁」这种冷开场。「谁更被看好」一律用**概率口径**（市场隐含可能性 vs 模型可能性 + 爆冷），讲成「球队热度 / 外界看好 vs 数据更冷静」，**绝不出现赔率、庄家、金额、资金**。

### 亮点 3 · 音频即时间基准 + 确定性渲染 = 音画帧级同步

先合成语音、量得精确时长，再据此排布 GSAP 动画时间轴，最后用 hyperframes 无头 Chrome **确定性**逐帧渲染。因为「时间真相」只有一份（音频清单里的 `startSec/durSec`），字幕、动画、数字人全部钉在它上面，所以 VERIFY_AV 能用 ffprobe 断言成片时长与清单误差 ≤ 0.5 秒——「口播说到哪，画面就到哪」不是靠对齐，是靠**同源**。

### 亮点 4 · 数字人主播 + AI 生成美术，且「缓存-only、绝不卡大脑」

- **数字人主播**（LongCat-Video-Avatar）：画面底部一条数字人口播带，替代传统字幕条，暗示「有人在讲」。双人播客是左右双人、按说话人时间轴冻结沉默一方。
- **gpt-image-2 美术**：Act-1 封面（写实双队海报，含国旗/队色/纹章/球员气质）与全片背景底图由 gpt-image-2 生成；配置了图像部署时**强制固化**，缺图会阻塞重试而非偷偷降级成灰底。团队徽标（crest）也由 gpt-image-2 生成并持久化缓存。
- **关键工程约束**：数字人生成会**抢占 GPU、暂停同机的 Qwen 大脑约 10 分钟**。因此流水线里的 AVATAR 阶段被设计成**纯缓存消费**——只从版本库 `assets/avatar-clips/` 取片、绝不联网、绝不触发生成。真正的生成放在**带外命令** `harness avatar-prewarm` 里手动做，独占锁 + 健康探针 + 「等大脑回来」屏障。一次正常 `harness run` 永远不会把大脑卡住。RENDER 再用「正放+倒放」的乒乓循环把短片铺满整条视频。

### 亮点 5 · 专属音色克隆 + 音色一致性攻坚

- **Qwen3-TTS 自定义音色**：每次运行可指定音色（`--voice` / 分角色 `--voice-male/female/narrator`），或用 `--clone-ref <参考wav>` **现场克隆任意嗓音**。
- **固定随机种子 `QWEN_TTS_SEED=7`**：Qwen3-TTS 是生成式模型，不固定种子时同一句话时长能抖 ~57%、「像不同人」。固定种子把一个角色的每一段都锚成「同一个人」。
- **女主播 x-vector 克隆**：活泼女声曾漂移到「像好几个人」（是男声抖动的 ~5 倍），改用固定 x-vector 参考音 `anchor_ref.wav` 克隆后，漂移降到与男声基线相当。

## 四、工程化与可运维亮点

| 能力                       | 说明                                                                                                                               |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **CLI 优先、无 MCP** | 稳定接口是`harness` 命令行，任意 coding-agent / MAF agent 都能直接驱动                                                                          |
| **MAF 托管 agent**   | 容器化封装成 Microsoft Agent Framework agent，RESPONSES 协议 :8088，暴露`generate_match_video` 单工具，大脑仍是 GX10 Qwen3.6-35B |
| **优雅降级**         | 无 LLM→模板；无 TTS→占位音；无 Chrome→跳过渲染；数字人缺失→占位带（WARN 不阻塞）                                               |
| **断点续跑**         | 每阶段产物落盘`out/`，`--from/--to` 任意区间重跑，TTS 结果按内容 SHA 缓存                                                      |
| **Jina Reader 抓取** | `scripts/fetch-jina.mjs` 把任意 URL 转成 LLM 友好的 Markdown/HTML 入库                                                           |
| **可硬失败**         | 关键产物（封面/背景/数字人）可配置为「缺失即阻塞重试」，避免静默出残次品                                                           |

## 五、技术栈一览

- **语言 / 运行时**：TypeScript（ESM）、Node.js ≥ 22
- **大模型**：GX10 本地 **Qwen3.6-35B**（思考型，OpenAI 兼容）→ Azure `gpt-5.4` 兜底
- **语音**：**Qwen3-TTS**（CustomVoice / ICL 克隆 / x-vector）→ Azure Speech 兜底 → 正弦占位
- **数字人**：**LongCat-Video-Avatar**（GX10 网关）
- **AI 美术**：Azure **gpt-image-2**（封面 / 背景 / 队徽）
- **渲染**：Handlebars 模板 + GSAP 动画 + ECharts 图表 + **hyperframes** 无头 Chrome + **FFmpeg**
- **数据**：`cheerio`（HTML 解析）、`zod`（全产物 schema）、`yaml`（配置）
- **Agent**：Microsoft Agent Framework（`agent-framework-openai` + `foundry-hosting`，精简依赖）
- **编排**：自研 plan-exec-verify 状态机 + supervisor（重试/回滚/问题路由/升级）
